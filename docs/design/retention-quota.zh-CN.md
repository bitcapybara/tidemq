# 保留与容量

逻辑保留下界、对象发布上界和本地正文回收上界分别表示不同事实。`retention::RetentionState` 与生产 offset、订阅 cursor 在同一数据组应用；它只允许下界单调前进到最低保留年龄和全部活跃订阅 ACK 前沿共同允许的位置。订阅创建、删除、向后 seek 与下界前进在同一个 apply 顺序内检查，不能通过旧的诊断结果授权删除。

新批次在生产者完成校验、预留容量且尚未修改正文时登记提交时间范围。重复批次直接返回原结果，不刷新消息年龄。时间范围按一秒向上取整，最多多保留不足一秒；新批次不会刷新旧时间桶的年龄。运行时提供可信时间，不能采用客户端时间；跨节点运行需维护受控时钟偏差，时钟异常期间暂停回收。时间窗口用逻辑单调值处理向后跳变。

默认最低保留一小时、最多 8192 个时间边界。配置必须至少容纳最低保留期对应的秒数再加一个边界。长期未 ACK 会让窗口继续增长；达到固定上限时明确背压新生产。不会通过合并旧时间范围把未确认数据淘汰，也不会无限分配时间索引。安全前进下界会释放相应窗口并恢复准入；原生产结果重试、ACK、控制和回收不应受该新写预算阻塞。

当前提交验证独立的有界状态、年龄/ACK/CAS 共同约束和序列化恢复。接入真实 DataApplication、对象生命周期与运行入口后的证据在集成验收记录中更新；单独通过状态测试不构成完整回收链路已完成。
