# 保留与容量

逻辑保留下界、对象发布上界和本地正文回收上界分别表示不同事实。`retention::RetentionState` 与生产 offset、订阅 cursor 在同一数据组应用；它只允许下界单调前进到最低保留年龄和全部活跃订阅 ACK 前沿共同允许的位置。订阅创建、删除、向后 seek 与下界前进在同一个 apply 顺序内检查，不能通过旧的诊断结果授权删除。

新批次在生产者完成校验、预留容量且尚未修改正文时登记提交时间范围。重复批次直接返回原结果，不刷新消息年龄。时间范围按一秒向上取整，最多多保留不足一秒；新批次不会刷新旧时间桶的年龄。运行时提供可信时间，不能采用客户端时间；跨节点运行需维护受控时钟偏差，时钟异常期间暂停回收。时间窗口用逻辑单调值处理向后跳变。

默认最低保留一小时、最多 8192 个时间边界。配置必须至少容纳最低保留期对应的秒数再加一个边界。长期未 ACK 会让窗口继续增长；达到固定上限时明确背压新生产。不会通过合并旧时间范围把未确认数据淘汰，也不会无限分配时间索引。安全前进下界会释放相应窗口并恢复准入；原生产结果重试、ACK、控制和回收不应受该新写预算阻塞。

当前提交验证独立的有界状态、年龄/ACK/CAS 共同约束和序列化恢复。接入真实 DataApplication、对象生命周期与运行入口后的证据在集成验收记录中更新；单独通过状态测试不构成完整回收链路已完成。

## 水位与内存观察

`quota::Quota` 分开记录逻辑积压、物理存储、共享对象回收滞后和进程内存。每种口径有高、低水位：触及高水位限制新生产，低于或等于低水位才恢复，处于中间区间保留原状态。默认分别为 128/96 MiB、256/192 MiB、64/48 MiB、256/192 MiB。前台消费、ACK、控制及 GC 不经过新生产水位；可选预取、缓存和后台快照在内存压力时停止扩张，它们仍受各自内存准入上限约束。

没有观测样本或样本超过一秒时拒绝新增可选工作。额度是软水位，硬约束仍由真实状态容量和在途字节准入执行；采样间隔内的并发工作必须计入容量余量。不会把采样值当成数据可删除或已经持久化的证据。

`quota::memory::MemorySampler` 每实例最多一项后台采样；外层超时后，后台工作继续持有槽位直到实际结束，避免诊断失败无限堆积线程。Linux 读取有字节上限的 `/proc/self/status` 与 cgroup v2 `memory.current`/`memory.max`；macOS 使用当前任务的 Mach RSS。cgroup v1、缺失字段及无限制 cgroup 均以不可用字段呈现，不填 0。容器总用量与进程 RSS 分开展示；RSS 本身已经包括分配器和原生驻留页，不能再把它们相加。Linux 实机采样仍待对应环境验证，解析边界测试已在本地运行。

部署容量表必须同时保留应用、原生 QUIC/TLS/S3、线程栈、诊断和分配器保留余量；`MemoryEnvelope::validate` 检查这些非重叠预算的合计不越过进程预算。分配器 stats/profile 继续使用对应 backend，不能用 allocator resident 冒充进程 RSS。采样器不选择全局分配器、安装 subscriber 或创建 exporter；这些设施由服务端二进制统一初始化。

当前验证包括高低水位迟滞、全水位下 ACK/控制准入、样本过期、有限指标 series、RSS 真实采样、字段单位/溢出与 cgroup 路径逃逸拒绝。运行入口与持久保留索引的最终接入仍在后续组合提交进行。
