# 保留与容量

逻辑保留下界、对象发布上界和本地正文回收上界分别表示不同事实。`retention::RetentionState` 与生产 offset、订阅 cursor 在同一数据组应用；它只允许下界单调前进到最低保留年龄和全部活跃订阅 ACK 前沿共同允许的位置。订阅创建、删除、向后 seek 与下界前进在同一个 apply 顺序内检查，不能通过旧的诊断结果授权删除。

新批次在生产者完成校验、预留容量且尚未修改正文时登记提交时间范围。重复批次直接返回原结果，不刷新消息年龄。时间范围按一秒向上取整，最多多保留不足一秒；新批次不会刷新旧时间桶的年龄。运行时提供可信时间，不能采用客户端时间；跨节点运行需维护受控时钟偏差，时钟异常期间暂停回收。时间窗口用逻辑单调值处理向后跳变。

默认最低保留一小时、最多 8192 个时间边界。配置必须至少容纳最低保留期对应的秒数再加一个边界。长期未 ACK 会让窗口继续增长；达到固定上限时明确背压新生产。不会通过合并旧时间范围把未确认数据淘汰，也不会无限分配时间索引。安全前进下界会释放相应窗口并恢复准入；原生产结果重试、ACK、控制和回收不应受该新写预算阻塞。

当前提交验证独立的有界状态、年龄/ACK/CAS 共同约束和序列化恢复。接入真实 DataApplication、对象生命周期与运行入口后的证据在集成验收记录中更新；单独通过状态测试不构成完整回收链路已完成。

## 水位与内存观察

`quota::Quota` 分开记录逻辑积压、物理存储、共享对象回收滞后和进程内存。每种口径有高、低水位：触及高水位限制新生产，低于或等于低水位才恢复，处于中间区间保留原状态。默认分别为 128/96 MiB、256/192 MiB、64/48 MiB、256/192 MiB。前台消费、ACK、控制及 GC 不经过新生产水位；可选预取、缓存和后台快照在内存压力时停止扩张，它们仍受各自内存准入上限约束。

没有观测样本或样本超过一秒时拒绝新增可选工作。额度是软水位，硬约束仍由真实状态容量和在途字节准入执行；采样间隔内的并发工作必须计入容量余量。不会把采样值当成数据可删除或已经持久化的证据。

`quota::memory::MemorySampler` 每实例最多一项后台采样；外层超时后，后台工作继续持有槽位直到实际结束，避免诊断失败无限堆积线程。Linux 读取有字节上限的 `/proc/self/status` 与 cgroup v2 `memory.current`/`memory.max`；macOS 使用当前任务的 Mach RSS。cgroup v1、缺失字段及无限制 cgroup 均以不可用字段呈现，不填 0。容器总用量与进程 RSS 分开展示；RSS 本身已经包括分配器和原生驻留页，不能再把它们相加。Linux 实机采样仍待对应环境验证，解析边界测试已在本地运行。

部署容量表必须同时保留应用、原生 QUIC/TLS/S3、线程栈、诊断和分配器保留余量；`MemoryEnvelope::validate` 检查这些非重叠预算的合计不越过进程预算。分配器 stats/profile 继续使用对应 backend，不能用 allocator resident 冒充进程 RSS。采样器不选择全局分配器、安装 subscriber 或创建 exporter；这些设施由服务端二进制统一初始化。

当前验证包括高低水位迟滞、全水位下 ACK/控制准入、样本过期、有限指标 series、RSS 真实采样、字段单位/溢出与 cgroup 路径逃逸拒绝。运行入口与持久保留索引的最终接入仍在后续组合提交进行。

cgroup v2 另有独立 headroom 门：观察当前组及至可见挂载根最多 64 层的 `memory.current`/`memory.max`，选择使用比例最高的有限祖先，包含兄弟进程对共同祖先的占用。当前组 `max` 不能掩盖祖先有限约束；不把最小 limit 与不对应的 current 拼接。达到 90% 停止新生产、预取、缓存和可选快照，回落至 80% 才恢复。RSS 与容器用量分别检查、分别诊断，不能相加。

有限、明确无限、平台不支持和读取不可用是不同状态。已需要 cgroup 约束后读取失败或突然变成不支持，新增工作保守拒绝；字段不全或样本陈旧也不准入。消费、ACK、控制和 GC 继续使用各自有限资源。字段诊断呈现选中祖先的 current/limit，但不导出祖先路径作为指标标签。不可见祖先和其他进程未来增长无法由本进程保证，部署仍须预留内存及约束同组工作；Linux 实机与隔离 OOM 实验尚未运行。依据为 [Linux cgroup v2 memory controller](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html#memory)。

## 持久组合与口径

DataApplication 的每个分区现在持有 RetentionState；生产新批次通过 append_admitted 原子登记时间和逻辑字节，重复批次不登记。floor 前进复查同一个 apply 锁内的实际 committed_end 与全部活跃订阅最小 ACK 前沿，并同步生产者的逻辑下界。生产者原结果、消息 offset 和 local_reclaim_end 保持各自含义；floor 前进不隐含上传或正文回收。时间采用批次携带的可信服务端准入时间，不使用客户端时间。

`capacity_usage()` 每组只遍历有硬上限的分区，逐分区对有界时间索引做二分查询，不扫描消息正文。逻辑积压字节是保守上界：ACK 前沿落在一个秒级时间桶内部时，整个桶仍计入；前沿抵达桶尾才扣除，全部确认或无活跃保护订阅时为 0。本地热正文是精确逻辑字节；未发布正文是保守上界，不能把它当作 S3 物理容量。元数据 Catalog 的登记对象空间与实际 WAL journal 空间须由运行时另行组合。

`ack_state_logical_bytes` 单独累计实际保留的订阅、身份/保护索引、交付 record 与重试索引结构，不包含消息正文。乱序 ACK 造成的孔尚未释放 record 时仍计费，连续前沿推进后才下降。该逻辑口径用于 ACK 状态负载评分；B-tree 节点空余容量、分配器页和 RSS 另看，不能把这个值当作完整 heap 的硬上界。

归档候选采用不超过 64 分区的键游标分页。游标按最后访问分区推进，已经发布完的分区也占本页位置，防止空候选页反复扫旧记录。构建 pack、seek、GC 均需各自新鲜权威与原有持久协议，容量样本不构成授权。

DataApplication 磁盘应用格式升级为 version 2，拒绝将旧格式目录当作新格式继续使用。本开发分支尚无历史格式迁移器；已有测试数据目录需要以匹配版本的二进制恢复，禁止自动清空或隐式重置。真实 RF1 回归已覆盖年龄与未 ACK 保护、持久 floor、floor 下 seek 拒绝、快照/purge/重启后 floor 与原生产结果、原 ACK 一致。

磁盘容量使用 `quota::disk::DiskSampler` 对固定配置的数据目录执行 statvfs：available 排除文件系统保留块，乘法溢出、无效路径、权限或挂载不可达均返回错误。与 RSS 采样复用单 owned worker 的期限控制，不接受 RPC 请求中的任意文件路径。容量迁移只采用目标节点自己获得的新鲜样本。
