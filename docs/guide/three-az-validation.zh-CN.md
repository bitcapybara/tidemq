# 真实三可用区验证准备

这是获批计划阶段 F 的执行清单。当前本地实验在 macOS、同一宿主和回环网络运行；正式验收以目标 Linux、真实三个故障域和用户确认的资源预算为前提。批准开发计划没有授权创建付费资源。当前尚无云资源变更或生产性能承诺。

2026-10-20 用户指定先在 `ssh dev` 上使用 Docker 做隔离验证。该步骤使用[独立 RF1/RF3 Compose 项目](../../deploy/docker/README.zh-CN.md)，先验证 Linux、资源限额、真实 SDK/QUIC/S3 和容器进程恢复，再决定真实三区资源。容器共享同一主机、内核和项目内网络 namespace，不能替代下面的跨区、独立节点网络或生产 LB 验收；本步骤不创建付费云资源。

## 必须冻结的输入

| 输入 | 执行前需要的具体值 |
| --- | --- |
| 环境与权限 | 云平台、Region、三个 AZ、已有节点/私网地址、受限访问方式、资源归属与清理负责人 |
| 费用 | 机器、WAL 磁盘/IOPS、跨区流量、S3 请求/容量/出流量、UDP LB、采集与日志的单价、运行时长和总预算上限 |
| 工作负载 | key/消息大小分布、消息/字节速率、批量/linger、固定分区/组/订阅数、并发/KeySerial、保留期与最大积压 |
| 容量余量 | 丢失一个区后的剩余 CPU/内存/磁盘/网络、归档中断窗口、修复带宽与控制/ACK 预留 |
| 接入与安全 | 一个稳定域名/UDP 入口、LB 的连接/CID/空闲行为、生产证书信任/轮换、静态令牌 scope 与秘密注入路径 |
| 产物身份 | 源提交、Cargo.lock、服务/SDK 与 RustFS/S3 版本、二进制哈希、符号、内核/libc、allocator/统计/profile 实际配置 |
| 验收口径 | RF3/fsync/quorum、Producer 持久 ACK 与逐消息持久 ACK、负载时长/重复次数、故障种子、失败/Unknown 计入方式 |

没有正式硬件和负载输入时不填虚构的每核吞吐、生产 allocator 或云成本。首版容量包括永久身份和对象账本硬上限（对象账本 4096）；目标规模超过任一硬上限时先修订容量设计并重新验证，不能以临时清账本绕过。

## 拓扑约束

元数据组的三个 voter 和每个数据组的三个 voter 各自一 AZ 一个，使用独立身份与持久目录。Broker/Gateway 至少放在两个 AZ，确保失去任一区后还有可用实例并有负载余量；可为每区部署一套。生产与元数据正文路径分离。是否同机组合由资源成本表明确，不能把同机多个进程算成独立故障域。

每个待迁移数据组预先列出有限 standby、证书/role/group 绑定与磁盘余量。新增 learner 追赶后才能进入 joint/stable；新成员必须满足三区约束。单区暂时失联期间，剩余多数派可继续服务，不能把三副本降为两副本，或把两个副本挤到同一区来伪装修复完成。入口和对象存储也需独立记录其故障边界。

## 执行顺序

1. 运行[完整本地正确性回归](../testing-benchmarks.zh-CN.md)，冻结 source/build/config；在目标 Linux 重跑 fmt/Clippy、持久化、实际 QUIC、S3、SDK、allocator 与采样自检。Linux cgroup v2 用独立测试资源组验证可见祖先 headroom；受控 OOM 只杀专用服务进程，随后用原身份目录恢复并校验全部已 ACK 数据。
2. 启动明确的三 AZ 拓扑，核对每个 voter、角色身份、证书和真实磁盘；等待实际 quorum/readiness。用原 SDK 创建身份、生产、冷读并持久 ACK，先建立正确性台账。
3. 用[性能工具](../performance.zh-CN.md)的相同持久语义跑固定负载。必要/推荐/详细三档、System/mimalloc/jemalloc 保持相同优化、总内存与线程预算；先校验同 allocator 栈诊断可行性，再选择生产默认与回退构建。采集器、LB、WAL/S3 资源一并计费。
4. 依次注入单 Broker、Gateway、Storage Leader、Metadata Leader 强杀，失去数据/元数据多数派，提交后丢响应，S3 限速/中断，learner/joint 中故障，计划 drain；每例保留原 Client/Producer/Consumer/PendingBatch，恢复后校验原结果、offset、cursor/attempt 和全部持久 ACK。
5. 使用专用网络隔离边界验证丢包/乱序/MTU/空闲/LB/NAT/CID；验证慢 B 回放、快照和修复时 C/ACK 仍推进。不在共享主机全局修改网络规则。相同总预算比较既有合法 stream 配置；连接隔离保持协议契约。
6. 真正隔离一个 AZ，记录客户端故障至持久成功的完整时间线，恢复该区并验证副本追赶、全 voter 检查点、原对象清单、冷数据、pin 和 GC。分别统计服务恢复和副本修复，不能把二者混为一个时长。
7. 对持续突发/排空/冷却、线程变化、慢订阅、ACK 空洞和归档中断跑长稳，记录积压斜率、逻辑状态/许可、allocator、RSS/cgroup 与物理空间；验证日志轮转/满盘、Collector 中断/恢复不会更改 quorum/ACK/GC 事实。
8. 汇总成功和失败样本、分位有效样本数、拒绝/Unknown/超时、总成本及全部运行身份。仅在持久语义和硬件资源一致时复现竞品。更新使用/设计/配置/告警与限制，清理明确归属的测试资源并保存账单与证据。

候选计划迁移通常 ≤1 秒、单 Broker/Gateway P99 ≤5 秒、单区 P99 ≤10 秒在此阶段核验。计时从实际故障开始，到受影响原 SDK 得到新的持久成功，包含探测、选举、fence、恢复、路由和重连；测试函数总用时不能作为该值。样本不足或任一正确性条件失败时，目标保持未验证。
